## Multiplayer

- [x] **Prototype host-authoritative multiplayer with a lightweight relay.** Build an optional standalone relay executable that forwards traffic without simulating the game. Add session/peer networking APIs and basic networked entity/component replication; demonstrate a two-player example. Keep database dependencies optional/not required for the initial relay. Consider third-party relay providers as alternatives; leave full dedicated authoritative servers for a later phase.
  - October 11: added the first self-hosted TCP room relay and optional, renderer-independent `rune:network` client API. Rooms support one host and up to seven guests, authenticated sender IDs, host-only guest routing, broadcast/targeted host messages, bounded queues, traffic limits, heartbeats, and disconnect cleanup. See [self-hosted relay](docs/networking.md). Unreliable UDP transport, transport encryption, and stronger public-server admission remain follow-on work.
  - Verification: all six client/protocol/server unit tests and the loopback relay validator pass on Windows and Linux. Separate relay/host/guest processes exercise authoritative input/state exchange and both departure paths; host closure also passes five consecutive Windows runs. The full Windows build/project checks complete, but existing parallel UI tests crash; all 12 UI tests pass when rerun serially.
  - Source layout: the standalone application and room-management package live in [`rune_relay/`](rune_relay/README.md); `rune/network` contains the client API and shared protocol/transport. Build the server as `build/rune_relay` (`.exe` on Windows).
  - October 11: added optional `rune:replication` for host-assigned entity identities and 2D transform positions, and converted [Relay Arena](examples/relay_multiplayer/README.md) into a real two-player Rune scene. The host simulates movement at 60 Hz; guests send held input and receive full position snapshots at 20 Hz. Joining, departure, replacement guests, input expiry, stale/malformed messages, and room closure are covered. Nine replication tests, four gameplay tests, and the real-relay ECS validator pass on Windows and Linux; separate-process runs exercise both platforms, and both rendered player views pass Windows visual checks. This completes the prototype; arbitrary component replication and the transport/gameplay follow-ons remain future work.
  - October 11: added an in-window Host/Join menu, editable relay address, normalized room-code paste, code copying, connection cancellation and retry, and return-to-menu controls. Default launch opens the menu; direct host/join/headless flags remain available. All 17 example tests pass on Windows and Linux, including real-relay menu connection and retry flows; menu and session controls pass Windows visual checks.
  - October 11: added 60 Hz guest movement prediction, processed-input acknowledgements and replay, bounded input history, remote interpolation, and visual correction smoothing to Relay Arena. Data sends flush immediately and explicitly enable TCP_NODELAY. All 36 example tests and 10 network tests pass on Windows and Linux; separate relay/host/guest sessions verify 60 input messages per second, 20 snapshots per second, and process cleanup. Windows hidden-window checks also pass. General prediction for arbitrary components remains outside this example's scope.
  - October 11: removed extra snapshot interpolation from the host's view of the guest, added bounded host-time input catchup, and flushed relay forwarding to earlier connections in the same server update. Regression checks cover immediate host display, backlog recovery during continuous input, movement budgets, cumulative prediction acknowledgements, and both relay connection orders. All 40 game and two relay server tests pass; Windows headless and hidden-window sessions and Linux launcher sessions show no sustained input queue growth.
  - October 11: user session logs exposed input queues stuck seven and 40 commands behind after window stalls. Moved the host input budget to monotonic wall time, retaining bounded recovery time beyond the renderer's delta clamp and preserving the small idle reserve across input expiry. All 43 gameplay tests pass on Windows and Linux, including the observed large backlog and timeout recovery; launcher sessions pass on both platforms. Controlled Windows probes recover 61 queued commands after a one-second host stall in 22 ms, and a seven-command guest resume batch in 6 ms; subsequent queues stay at zero or one. Added a balanced Windows timer-resolution request after measuring the relay's 2 ms sleep rounding to roughly 16 ms; the request reduced it to roughly 3 ms in the timing probe.
  - October 11: added authenticated UDP gameplay alongside reliable TCP room controls, enabled by default in Relay Arena and configurable with `udp_enabled` / `--udp` / `--no-udp` on the relay and `--transport udp|tcp` on the example. UDP uses random session tokens, endpoint binding, replay filtering, retry/deadline handling, and bounded datagrams. The example repeats the oldest unacknowledged input prefix and retains bounded elapsed host time to recover packet loss without lost movement or permanent queue delay. All 55 game, 18 network, 13 relay server, eight config, and 14 launcher tests pass on Windows and Linux; real sessions report UDP traffic in both directions, and the relay passes an Apple Silicon source check. General ECS replication, encryption, reconnect/resume, and public-server admission remain future work.

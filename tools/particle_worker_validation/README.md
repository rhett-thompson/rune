# Particle worker validation

Run from the Rune root. The default invocation checks serial/worker simulation
and billboard stream parity without creating a window. `--runtime` adds hidden
engine and R3D windows, which require a working graphics context/display.

```powershell
./tools/odin.ps1 -OdinArguments @('build','tools/particle_worker_validation','-collection:rune=rune','-collection:r3d=third_party/r3d-odin','-linker:msvc','-out:build/particle_worker_validation.exe')
./build/particle_worker_validation.exe
./build/particle_worker_validation.exe --runtime
```

On Linux use `sh tools/odin.sh build ...`, omit `-linker:msvc` and `.exe`, then
run the executable from the same working directory.

The CPU checks compare 2D emission, RNG/credit, hierarchy, expiry, disabled and
removed emitters; 3D live-prefix motion/expiry; and three prepared billboard
batches with depth ties, invisible and invalid input. They verify unchanged
source bytes, warm owner allocation reuse and actual worker execution of the
billboard classification/finalization callbacks. Partial reservation failures
must publish empty streams, exclude failed destinations from jobs and recover
on a later owner preparation. Guarded allocators reject any worker allocation
attempt through retained arrays or the callback context. Full queues and occupied
workers with spare queue space must return before a watchdog releases unrelated
gated callbacks.

Large fixtures derive their counts from the production dispatch constants, so
raising a heuristic does not silently turn worker regressions into scalar
checks. The engine fixture starts at the 2D work gate; 3D live pools and direct
billboard preparation also reach their respective gates. Large pools live on
the heap, keeping the default process stack limit unchanged.

The runtime branch runs six frames through the real engine scene loop with a
configured three-worker pool and compares 2D states and offscreen render pixels
against a scalar World. Ordinary R3D scene draws then compare scalar/worker
pixels, CPU instance streams and GPU POSITION/SCALE/COLOR buffer readbacks across
three billboard batches, sphere fallback, alpha/additive modes, camera turns,
empty frames and reuse. Multiple batches must retain separate live GPU buffers.

Inputs generated by this tool stay under ignored `build/` fixture directories.
The tool closes its windows, joins its helper threads and drains/destroys pools.
These correctness checks do not measure a speedup or prove GPU behavior on
platforms where the runtime branch has not been run.
